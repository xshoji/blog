WebMCP は「 AI に Web UI を中抜きさせない」 ための規格なのか

はじめに

Cloudflare が「 Give any website a WebMCP interface 」という記事を公開した。

WebMCP を有効にすると、 Cloudflare が HTML へ bridge script を挿入し、ブラウザ内の AI エージェントが利用できる Tool をページへ登録するという。 つまり、サイトのオリジン側には変更が要らない。

Give any website a WebMCP interface
https://blog.cloudflare.com/webmcp/
─
Today we are launching a developer preview of WebMCP on Cloudflare. Switch it on and browser agents can start working with your site, with no code and nothing changed at your origin. Cloudflare adds a small bridge to your pages, which registers a set of tools for a visitor’s agent to use.
本日、 Cloudflare における WebMCP の Developer Preview を開始します。有効にすると、コードやオリジン側の変更なしに、ブラウザエージェントがサイトを操作できるようになります。 Cloudflare はページへ小さな bridge を追加し、訪問者のエージェントが利用する Tool 群を登録します。

そもそも WebMCP について詳しく知らなかったため、まず仕様と公式ドキュメントを調べたところ、 AI エージェントが Web サイトを効率よく操作するための API であることがわかった。 画面を見てボタンを探す代わりに、ページが操作可能な機能を構造化された Tool として渡す。 これによりエージェントの操作は速く、安定する。

用途は理解できるが、 AI エージェントが DOM や Accessibility Tree から画面を理解できるなら、サイト側が追加実装してまで Tool を用意する必要はあるのか疑問を持った。

そんな中、 WebMCP の公式 README に、操作精度以外の目的を示す一節があった。

Prevent web content disintermediation

WebMCP は、 AI エージェントに Web を「中抜き」させないための規格でもあるのだろうか。
